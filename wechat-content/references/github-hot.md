# GitHub 热门栏目模板

- 栏目标识使用“开源坐标”。
- 使用编辑卡片式单栏结构。动态开头说明本周共同变化或诚实采用“多条路线”，不描述机械搜索过程；动态结尾回看本期项目，不复用固定套话。
- 开头和结尾必须面向读者，不得出现“模板”“生成”“采集过程”“审核过程”“只保留读者真正会用到的信息”等内部设计话术。多路线开头应先给出吸引人的判断，再落到本周具体方向；结尾应给出“马上试用 / 系统学习 / 当前工作最接近”等可执行选择。
- schema v2 默认呈现 GitHub Trending weekly 前 10 个项目；每个项目依次呈现：编号与项目名、类别标签、描述、项目图、语言/Star/本周新增/Fork、一句话概况、3 个重点内容、适合谁和完整官方地址。
- `描述` 优先使用 `reader_card.translated_description`，它是 GitHub Trending 或仓库官方描述的中文忠实表达；不得用编辑概况、推荐语或适合谁替代。
- `一句话概况` 使用推荐语或编辑摘要，回答“为什么值得看”；`适合谁` 只写目标读者或使用者，避免和概况混在一起。
- 周增 Star 为 `null` 时整项省略，绝不显示为 0。
- 完整 README、许可证、Commit、Release、维护状态、指标核验时间、内部风险、证据、未入选原因和图片审核信息放在复制区外的运营审核台。
- 许可证、维护证据和内部风险全部留在复制区外；明显安全问题应在研究层淘汰，不能靠正文警告补救。
- 结尾观察开发者正在解决的问题，并邀请读者选择想尝试或推荐的项目。
- 每个项目都要尝试使用官方图，但正文只展示真正可用的项目图：优先使用研究包中 `usage_status: approved` 的官方真实截图；其次使用依据已核验用途生成的 Image2 项目图；两者都不可用时，该项目不展示图片，禁止用低质本地项目卡硬凑。
- 即使没有传入 `--project-image-dir`，也要直接消费内容包 `visual_candidates` 中已核验的 `approved` 官方截图 URL；渲染时自动下载并等比放入 1200×675 正文画布，下载失败或尺寸异常时只在 manifest 记录原因，并从读者正文移除该项目图片。
- 整篇 GitHub 热门正文项目图少于 3 张时，插入文章级主题图补足：优先读取 `--image-input-dir/articles/NN.png` 的 Image2 图；没有时使用本地科技主题图。主题补图服务整篇文章，不绑定单个项目，不冒充官方截图。
- 封面优先使用 `--image-input-dir/cover.png` 中的 Image2 无字科技底图，再由本地脚本叠加准确中文标题；底图建议采用开源雷达、项目节点、代码路线图和深蓝冷光科技风，缺失时使用本地 GitHub 封面模板，本地模板必须体现本周 10 个项目节点和路线，不得退化为空泛插画。
- 正文图表达项目用途和代码连接，不虚构真实产品界面、Logo、文字或数据。
- 配色遵循“品牌稳定、主题半动态”：深蓝科技品牌骨架固定，强调色按 AI、开发工具、创意工具、系统数据或混合主题确定，并记录在清单中；项目块保持统一结构，只做轻微类别强调，避免 10 个项目各自变成完全不同的模板。
- 规则、模板和样式全部内置，不依赖 `wechat-article-writer`，只安装本 Skill 也能复现。
